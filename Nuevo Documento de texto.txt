MASTER PROMPT — PLANIFICACIÓN COMPLETA DE UNA PLATAFORMA DE COMERCIO ALGORÍTMICO
CONTEXTO DEL PROYECTO
Estamos diseñando una plataforma de ecommerce radicalmente enfocada en conseguir para el usuario la mejor oferta posible.
La plataforma NO debe plantearse inicialmente como:
	•	un marketplace tradicional;
	•	un simple comparador de precios;
	•	otra tienda online;
	•	una alternativa a TikTok Shop;
	•	una alternativa a Amazon, Temu, AliExpress o Alibaba.
La idea es construir una capa de comercio algorítmica que pueda recibir un producto descubierto por el usuario —por ejemplo desde TikTok— identificarlo, encontrar ese producto o equivalentes válidos entre múltiples fuentes, calcular el precio final real, y permitir que el usuario lo compre desde nuestra propia interfaz.
Para el usuario debe sentirse como una tienda normal:
Producto → precio → comprar → checkout → pedido → entrega.
Pero detrás de escena, nuestro sistema debe decidir dinámicamente cuál es la mejor manera de conseguir y cumplir ese pedido.
Puede haber múltiples fuentes:
	•	AliExpress
	•	Alibaba
	•	Temu
	•	Amazon
	•	Mercado Libre
	•	tiendas independientes
	•	proveedores directos
	•	distribuidores
	•	feeds de productos
	•	APIs oficiales
	•	programas de afiliados
	•	proveedores con acuerdos directos
	•	futuras fuentes adicionales
No asumamos que todas estas fuentes permitirán integración directa. Debemos investigar técnicamente, legalmente y comercialmente qué mecanismos son posibles para cada fuente.


⸻


PRINCIPIO FUNDAMENTAL DEL PROYECTO
La prioridad número 1 de toda la arquitectura es:
MINIMIZAR EL PRECIO FINAL PARA EL CLIENTE.
No maximizar margen.
No maximizar markup.
No maximizar revenue por pedido.
No intentar ganar una cantidad fija por producto.
La filosofía es:
Ser la mejor oferta posible.
Ejemplo:
TikTok: $108 MXN
Proveedor A: $105
Proveedor B: $103
Proveedor C: $101
Nuestra plataforma podría vender a:
$102 MXN
Margen: $1 MXN.
Eso es perfectamente aceptable si permite que el usuario tenga la mejor oferta.
Incluso puede haber productos con:
$0 de margen
si estratégicamente tiene sentido.
En determinados casos podría incluso analizarse operar con margen negativo controlado como estrategia de adquisición, pero esto debe ser una decisión explícita y limitada, nunca accidental.
El sistema debe tratar el margen como una restricción/variable secundaria, no como el objetivo principal.

PRECIO FINAL REAL
No solamente el precio del producto.

Producto comparable + condiciones comparables + costo total comparable.

TERCER PRINCIPIO
Nunca asumir que dos productos son iguales solamente porque tienen títulos parecidos.
Necesitamos un sistema robusto de:
PRODUCT MATCHING
Debe poder analizar:
	•	título;
	•	descripción;
	•	imágenes;
	•	marca;
	•	modelo;
	•	SKU;
	•	UPC/EAN/GTIN cuando exista;
	•	atributos;
	•	color;
	•	talla;
	•	capacidad;
	•	dimensiones;
	•	materiales;
	•	especificaciones;
	•	variantes;
	•	contenido del paquete;
	•	vendedor;
	•	fabricante;
	•	categoría.
Debe distinguir entre:
Exact Match
Es esencialmente el mismo producto.
Variant Match
Es el mismo producto pero una variante diferente.
Equivalent
No es idéntico, pero puede considerarse una alternativa funcional.
Similar
Se parece, pero no debería presentarse como el mismo producto.
Unknown
No hay suficiente confianza.
No permitir que un producto similar se presente fraudulentamente como idéntico.

	1.	URL del producto.
	2.	URL de TikTok.
	3.	Imagen/screenshot.
	4.	Búsqueda textual.
	5.	Eventualmente navegador/extensión/app.

Lo pega en nuestra plataforma.
Nuestra plataforma:
	1.	identifica el producto;
	2.	extrae información;
	3.	encuentra candidatos;
	4.	realiza matching;
	5.	consulta precios;
	6.	calcula precio final;
	7.	encuentra la mejor fuente;
	8.	muestra nuestro producto;
	9.	permite comprar.
